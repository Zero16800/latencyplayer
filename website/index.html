Features

为直播而生的能力集

不是从 VOD 播放器上缝补的直播功能，而是从 RTMP 链路、解码、渲染每一层都按「低延迟、高可用」重新设计。

⚡

预连接毫秒级切流

preconnect(url) hold 模式：建连、CDN 突发灌入、突发积压消耗、第一个关键帧软解全部后台完成，同 URL 播放直接出画。

🎯

极限低延迟

bufferTime(0) + 内部队列扁平化（queue2 50ms / multiqueue 8 缓冲），稳态延迟数据实测中位 ~125ms，而非「参数上支持」。

🔄

追帧丢弃 · 抗积压

CDN 开播一次下发 ~2.5s 历史：appsink sync=FALSE + 按「直播边缘 − 帧 PTS」追帧，只跳帧不渲染旧帧，0.3s 内贴回直播边。

🛡

后台自恢复看门狗

进程被系统/MIUI 冻结后管线“假活”：逐秒检查最近帧年龄，>3s 无新帧强制重连，返回前台 ~750ms 内恢复出画。

🔌

不依赖 EGL 的直绘

RGBx/RGBA → ANativeWindow appsink 直绘，绕开 glimagesink 在模拟器/锁定设备上的兼容坑，稳定可测。

📡

断线自动重连

间隔、次数可配，maxReconnectCount(0) 无限次；URL 热切换 switchUrl 不销毁 pipeline。

🎛

软解/硬解可切换

openh264 软解为默认可预期路径，MediaCodec 硬解路径可按机型启用；H.264 主播级覆盖，AAC/MP3 等音频全支持。

📸

截图 / 帧年龄 / 回调齐全

saveSnapshot PNG/JPEG、getLastFrameAgeMs、首帧与视频尺寸主线程回调、onDownloadSpeed。

📦

体积认真做过

34 插件白名单链接 + strip + FFmpeg 符号本地化，AAR 59.6MB 全 ABI，链接期由 --no-undefined 强制校验。

Architecture

hold 模式：把等待都做在点击之前

常规播放器切流慢，是因为建链、CDN 突发、首帧解码全在点击「之后」串行发生。LatencyPlayer 的 preconnect 把这一切搬进后台，并在视频链真正可用时才放行。

  1. preconnect(url) 立即返回~200–400ms 返回，不阻塞调用线程；后台占用一条 RTMP 连接 + 一个软解码器。
  2. 后台直达 PLAYING 持续取流RTMP 建连 → CDN 突发一次下发 ~2.5s 历史 → 追帧丢弃消化积压 → 首个关键帧软解完成、playbin 视频链建立。
  3. hold 样本静默丢弃不向 Surface 出画、不触发 FIRST_FRAME，业务层完全无感知。
  4. play() 只需「放行」同 URL 直接 hold=FALSE，下一帧解码完成即出画——贴直播边缘的新帧，而不是历史帧。
普通播放器切流（串行） tap ─▶ 连接 ─▶ CDN 2.5s 灌入 ─▶ 首帧软解 ─▶ 出画 ~1000ms+ LatencyPlayer（预连接） t0 ─▶ preconnect(url) ─▶ [后台: 建链+积压+首帧解码] tap ─▶ 放行 hold ─▶ 出画 ~173ms avg
